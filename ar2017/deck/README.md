# Slide deck: Acemoglu & Restrepo (2017)

A marimo notebook in slides layout: 19 slides, about 20–25 minutes. Every number comes from the validated pipeline in `../results/`; nothing is estimated live.

## Present
```bash
marimo run deck/deck.py          # opens in the browser; arrow keys move between slides
```
- **After touching a control** (slider, radio button, checkbox), click an empty part of the slide before pressing the arrow keys. While a control has keyboard focus, the arrows go to the control: a radio button changes its selection instead of the slide advancing.
- **Speaker notes** are stored per slide in `layouts/deck.slides.json`. Open the notebook in the editor (`marimo edit deck/deck.py`) and switch to the slides layout to see and edit them.

## Backups (all three are already built in this folder)
| File | Interactivity | Needs |
|---|---|---|
| `deck_static.html` | Charts stay interactive (hover, sliders, toggles): every control is a client-side Vega-Lite parameter, so no Python is needed | A browser with internet (loads marimo's frontend from a CDN) |
| `deck_wasm.html` | Fully live: Python runs in the browser (Pyodide) | Internet; first load takes 20–40 s |
| `deck_slides.pdf` | None; each chart shows its default state | Nothing |

To rebuild them after an edit:
```bash
python3 deck/prep_data.py && python3 deck/make_layout.py
```
```bash
marimo export html deck/deck.py -o deck/deck_static.html -f
```
```bash
marimo export html-wasm deck/deck.py -o deck/deck_wasm.html --mode run --single-file -f
```
For the PDF, either run marimo's own export (it needs `pip install nbconvert playwright` and `python -m playwright install chromium`):
```bash
marimo export pdf deck/deck.py -o deck/deck.pdf --as=slides --raster-server live
```
or screenshot the running deck, which is how `deck_slides.pdf` was made:
```bash
node deck/tools/snap_slides.js http://localhost:2718 OUTDIR 19
```

## Files
| File | Role |
|---|---|
| `deck.py` | The notebook. One cell per slide; setup cells (theme, inline data, helpers) are skipped in the layout |
| `theme.css` | Light theme: ink `#0b0b0b`, navy `#2a4fa8` (series 1), green `#00a35f` (series 2), electric green `#2ee88f` (accents only). The series colors pass a color-vision-deficiency and contrast check |
| `layouts/deck.slides.json` | Slide types, transition, speaker notes. Generated by `make_layout.py`; rerun it after adding or reordering cells |
| `prep_data.py` | Writes `public/deck_data.json` and inlines it into `deck.py`, so every export is self-contained |
| `../results/fig3_robots_digitized.csv` | Figure 3 points recovered from the PDF's vector paths. They are validated: the x-values match the replication data exactly, and OLS on the points reproduces the paper's fit line |

## Content choices to review
- **Thesis wording (slide 2):** capital-rich economies gain more from each automated task. The model's cost of automating, C(θ), does not depend on K.
- **Analogy (slide 3):** one tool company sells to many builders and chooses how many steps its tools can do on their own (θ).
- **Theory slides 4–8** use an illustrative calibration: K = 3, L = 1, ηχ = 0.3, C(θ) = 0.05(−θ − ln(1−θ)). The paper picks no functional form.
- **θ > 0.8 bound (slide 9)** is our derivation, not the paper's. The proof is in the speaker notes.
- **The interaction (moderator) test is left out** by request. It appears only as a weakness bullet on slide 18.
